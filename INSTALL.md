# Lab Manager 0.1.0 — статусы и материалы

## Обновление существующего проекта

1. Сохрани все файлы и закрой Extension Development Host.
2. Сделай резервную копию папки исходников.
3. Скопируй src из архива в src своего проекта, объединяя папки и заменяя пять
   одноимённых .ts-файлов. Не удаляй src/test.
4. Замени package.json и INSTALL.md. Не меняй свои .vscode, tsconfig.json,
   eslint.config.mjs, package-lock.json и TZ.md вручную.
5. В терминале из папки с package.json выполни:

   npm install
   npm run compile
   npm run lint

6. Если ошибок нет, нажми F5.

Это обновление исходников, а не самостоятельный проект и не установочный VSIX.
Идентификатор lab-maneger и ключ labManager.projects не изменены.
Старые записи читаются с теми же id, названием, путём и предметом. Если status
отсутствует, используется «Не начата», если materials отсутствует — пустой список.
Дополненные данные записываются при следующем сохранении списка.
Никакого сброса данных при обновлении нет. При повреждённом формате выводится ошибка.

## Статусы

ПКМ по проекту → «Lab Manager: Изменить статус».
Возможны: «Не начата», «В работе», «Готова», «Сдана».
Статус отображается рядом с названием и отдельным значком.
В поиске видны название, предмет и статус.

Кнопка-воронка в заголовке «Учебные проекты» либо команда
«Lab Manager: Все / только несданные» переключает фильтр дерева.
Фильтр скрывает только статус «Сдана»; «Готова» считается ещё не сданной работой.
Скрытые записи не удаляются. Повторное нажатие возвращает все проекты.
Состояние фильтра сохраняется между запусками. Режим виден в заголовке панели.
Поиск через «Показать проекты» намеренно ищет по всем записям, независимо от фильтра.

## Материалы

ПКМ по проекту → «Lab Manager: Прикрепить материал».
Выбери «Локальный файл» или «Веб-ссылка», затем задай понятное название,
например «Условие», «Отчёт» или «Репозиторий».

Файл: выбирается существующий локальный файл; сохраняется только путь, не содержимое.
Поддерживаются PDF, DOCX и другие типы, для которых в системе есть приложение.
Ссылка: разрешены только HTTP и HTTPS. command:, javascript: и прочие схемы запрещены.
Наличие страницы и доступ к ней заранее не проверяются; ссылка открывается браузером.
Повторный файл или одинаковая нормализованная ссылка внутри одного проекта отклоняются.

После первого прикрепления возле проекта появляется стрелка. Раскрой её, чтобы
увидеть материалы. Нажатие на проект с материалами раскрывает дерево; саму папку
открывай через ПКМ → «Открыть проект» либо через поиск «Показать проекты».
Проект без материалов по-прежнему имеет команду открытия на строке.

Нажатие на материал открывает его системным приложением/браузером, а не обязательно
внутри VS Code. Для PDF/DOCX нужна установленная программа с ассоциацией этого типа.
Если система не может открыть файл, плагин сообщает об ошибке.

ПКМ по материалу:
- «Открыть материал».
- «Открепить материал» — с подтверждением, без удаления самого файла.
- «Изменить путь материала» — только для локального файла.

Для перемещённого/недоступного файла при открытии предлагается выбрать новое
расположение. После смены пути нажми на материал снова.
Удаление проекта удаляет из списка и его прикрепления, но не папку или материалы.

## Проверки у себя

1. Старый проект остался и получил статус «Не начата».
2. Смена статуса обновляет подпись и сохраняется после F5-перезапуска.
3. «Сдана» скрывается фильтром, повторное переключение возвращает запись.
4. Прикрепи безопасный PDF/документ и HTTPS-ссылку, раскрой проект и открой оба.
5. Дубликат материала и ссылка со схемой command: не принимаются.
6. Escape на каждом шаге добавления не создаёт прикрепление.
7. После перезапуска материалы остаются.
8. Открепление с отменой оставляет материал; подтверждение убирает запись,
   сам файл в файловом менеджере остаётся.
9. Перемести отдельный тестовый файл и проверь восстановление пути.
10. После добавления или редактирования сразу выполни другую операцию:
    информационные уведомления больше не держат блокировку busy.

## Что проверено при подготовке

Разбор синтаксиса пяти TypeScript-модулей и согласованность 13 команд с меню.
19 автоматических проверок с имитацией VS Code API: чтение старых данных,
значения по умолчанию, вложенные копии, отклонение некорректного статуса и схемы
ссылки, фильтрация, вложенные материалы, смена статуса, отсутствие блокировки на
информационных уведомлениях, добавление/открытие ссылки, отмена и подтверждение
открепления, сохранение фильтра.

Полная компиляция tsc, ESLint и настоящий интерфейс VS Code здесь не запускались:
в среде подготовки нет зависимостей твоего проекта и GUI VS Code.
Это нужно проверить локально командами выше, затем выполнить ручные проверки.

## Ограничения и сдача

Локальные проекты; один проект — одна корневая папка. Без облака, Git-операций,
тегов, статусов из внешних сервисов и автопоиска папок. Статусы выставляются вручную.
Группировка предметов учитывает регистр. Файлы не копируются и не синхронизируются.
Редактировать список рекомендуется из одного окна: межоконной транзакционной
защиты нет. При изменениях в другом окне нажми «Обновить список».

Код подготовлен с помощью ИИ. Условия лабораторной требуют обозначить использование
ИИ при сдаче. Обнови README, DOCS и отчёт новыми возможностями; этот INSTALL.md
не заменяет авторство и всю требуемую документацию.
