# Устройство Lab Manager

## 1. Общая идея

Lab Manager — расширение для VS Code, написанное на TypeScript.

Оно хранит список учебных проектов и показывает его
в боковой панели. Через команды пользователь может добавлять,
открывать и редактировать проекты, менять статусы
и прикреплять материалы.

Для интерфейса используются готовые возможности VS Code:
дерево элементов, поля ввода, списки выбора и уведомления.

## 2. Как расширение подключается к VS Code

Основные настройки находятся в `package.json`:
- название и версия расширения;
- поддерживаемая версия VS Code;
- список команд;
- описание боковой панели;
- пункты контекстных меню;
- путь к запускаемому JavaScript-файлу.

Исходный код написан на TypeScript. При сборке он преобразуется
в JavaScript и помещается в папку `out`.

VS Code запускает расширение в Extension Host — отдельной среде
для выполнения расширений. Взаимодействие с редактором
происходит через API из модуля `vscode`.

Функция `activate` создаёт дерево и регистрирует обработчики
команд. Ресурсы добавляются в `context.subscriptions`,
чтобы VS Code освободил их при отключении расширения.

## 3. Схема работы

```text
Действие пользователя
        ↓
Команда VS Code
        ↓
ProjectManager
        ↓
Проверка и обработка данных
        ↓
projectStorage → globalState
        ↓
Обновление дерева ProjectTreeProvider
```

При открытии проекта или материала данные обычно
не меняются: плагин проверяет путь и передаёт запрос
редактору, системному приложению или браузеру.

## 4. Основные файлы

### extension.ts

Точка входа расширения.

Создаёт менеджер проектов и дерево, подключает панель,
регистрирует команды и связывает их с обработчиками.

### project.ts

Описывает типы данных:
- `StudyProject` — учебный проект;
- `ProjectStatus` — статус работы;
- `ProjectMaterial` — прикреплённый материал.

Объект `STATUS_INFO` содержит подписи и значки статусов.

### projectStorage.ts

Отвечает за чтение, проверку и сохранение списка.

Основные функции:
- `getProjects` — получает проекты из хранилища;
- `saveProjects` — проверяет и сохраняет список.

Старые записи без статуса и материалов дополняются:
используется статус «Не начата» и пустой список материалов.

Если формат сохранённых данных некорректен,
плагин сообщает об ошибке, а не сбрасывает список.

### projectTree.ts

Содержит `ProjectTreeProvider`.

Он строит дерево из трёх уровней:

```text
Предмет
└── Проект
    └── Материал
```

Метод `getChildren` возвращает дочерние элементы,
а `getTreeItem` задаёт их подписи, значки и действия.

После изменения данных отправляется событие,
по которому VS Code обновляет дерево.

Здесь же работает фильтр несданных проектов.

### projectManager.ts

Содержит основную логику:
- добавление, открытие и редактирование проектов;
- удаление записей;
- изменение статусов;
- прикрепление и открытие материалов;
- изменение путей;
- диалоги и проверки;
- обработку ошибок.

## 5. Данные проекта

Каждый проект содержит:

| Поле | Назначение |
|---|---|
| id | Уникальный идентификатор |
| name | Название работы |
| path | Путь к папке |
| subject | Предмет |
| status | Статус работы |
| materials | Массив материалов |

Идентификатор создаётся через `randomUUID`.
Он не меняется при переименовании проекта.

Материал содержит собственный идентификатор, название,
тип `file` или `link` и поле `target` с путём либо адресом.

## 6. Используемые структуры данных

- Массив `StudyProject[]` — список проектов.
- Массив `ProjectMaterial[]` — материалы проекта.
- `Set` — получение уникальных предметов и проверка
  повторяющихся идентификаторов.
- `Record` — соответствие статусов их подписям и значкам.
- Объединение типов `ProjectTreeNode` — описание разных
  узлов дерева: предмета, проекта и материала.

Для обработки используются:
- `find` и `findIndex` — поиск записи;
- `some` и сравнение путей — проверка повторов;
- `filter` — отбор и удаление записей из списка;
- `map` — преобразование данных;
- `sort` — сортировка по названию.

## 7. Добавление проекта

1. Проверяется наличие одной открытой локальной папки.
2. Проверяется её доступность.
3. Проверяется, нет ли этой папки в списке.
4. Пользователь вводит название и предмет.
5. Создаётся запись с уникальным идентификатором.
6. Список сохраняется.
7. Обновляется боковая панель.

Перед сравнением пути нормализуются.
Для существующих папок учитываются символические ссылки.

Пустые строки не принимаются.
Отмена диалога не создаёт запись.

## 8. Статусы и фильтр

Внутри кода используются значения:
- `not-started` — Не начата;
- `in-progress` — В работе;
- `ready` — Готова;
- `submitted` — Сдана.

Статус пользователь выбирает вручную.

Фильтр скрывает из дерева только проекты со статусом
`submitted`. Исходный список при этом не изменяется.

Поиск проектов работает по всему списку,
независимо от фильтра дерева.

## 9. Материалы

Для локального материала сохраняется путь к файлу.
Для веб-материала — адрес HTTP или HTTPS.

Перед открытием файла проверяется его доступность.
Если файл перемещён, пользователь может выбрать новый путь.

Материалы открываются через `vscode.env.openExternal`:
файлы — системным приложением, ссылки — браузером.

Плагин не копирует документы и не загружает их на сервер.
Открепление удаляет только запись материала.

## 10. Хранение

Используется `context.globalState` — локальное хранилище
расширения в текущем профиле VS Code.

Ключи:
- `labManager.projects` — список проектов;
- `labManager.onlyUnsubmitted` — состояние фильтра.

Данные доступны при переключении между папками.
Синхронизация между компьютерами не настраивается.

Одновременное изменение списка из нескольких окон
не защищено транзакциями. Для первой версии рекомендуется
изменять список из одного окна.

## 11. Асинхронные операции и ошибки

Для ввода, выбора файлов и сохранения используются
`async` и `await`.

Флаг `busy` не позволяет начать вторую изменяющую операцию
в том же окне, пока не закончилась первая.
Он сбрасывается в блоке `finally`, в том числе при ошибке.

Обычные информационные уведомления показываются
без ожидания их закрытия, чтобы не удерживать блокировку.

Ошибки обрабатываются и выводятся пользователю.
Подробности записываются в консоль с пометкой `Lab Manager`.

## 12. Проверка работы

При ручном тестировании проверялись:
- добавление и сохранение проектов;
- редактирование и открытие папок;
- удаление записи без удаления файлов;
- смена статусов и фильтрация;
- прикрепление файлов и ссылок;
- открытие и открепление материалов;
- восстановление пути к перемещённому файлу;
- сохранение изменений после перезапуска.

Для проверки сборки и правил кода используются команды:

```bash
npm run compile
npm run lint
```

Эти команды не заменяют проверку интерфейса
и пользовательских сценариев.
